## Confirmed bugs

### 1. Initial Watch restore overwrites a new brief

Location: `src/app/page.tsx:975` and `src/app/components/watch-feed.tsx`.

The initial `watch_snapshot` calls `onBom`. When `activeRun.current` is empty,
`onBom` unconditionally replaces the goal and constraints, even if the user has
already edited them. A delayed snapshot was reproduced in a real browser:
the typed value was initially correct, then was overwritten, and the intercepted
submission contained the previous build. That reproduction created no real run.
An earlier real browser test was stopped when it unexpectedly planned a robot
arm instead of the intended Pico build.

The successful sourcing test waited for the initial snapshot before entering the
brief. This is a test workaround, not an application fix.

### 2. Search truncation removes buying intent

Locations: `src/server/adapters/parallel.ts:50` and `src/server/crawler.ts:28`.

The planner produced 239 characters of key specifications for the Pico. The
search adapter cuts each query to its first 200 characters, removing all four
commercial suffixes: buying price, distributor stock, supplier delivery and
retailer catalogue. Four intended searches became one identical submitted
search query. The accepted listings in this run were manufacturer PDFs/product
information rather than purchasable listings with an accepted price.

With concise requirements in the isolated Watch test, the crawler reached retail
pages and accepted stock evidence, but still did not accept a price. Therefore
fixing query construction alone has not been demonstrated to resolve price
sourcing; pricing needs a fresh live regression test after a fix.

### 3. Gmail parser expects a different response shape

Locations: `src/server/adapters/gmail-thread.ts:18` and
`src/server/adapters/gmail-thread.ts:47`.

Observed Composio messages expose `messageId`, `messageTimestamp`, `messageText`,
`preview`, `sender`, `payload` and `labelIds`. The parser instead requires `id`
and `internalDate`. Every recorded test thread failed Zod validation, including
threads containing only an unsent draft. The same failure was reported during
the real Watch cycle; other Watch work and Slack delivery continued.

Normalize the provider's documented/live fields before applying reply filtering
and grounding, and cover that shape with regression tests. An actual received
supplier quote remains untested.
